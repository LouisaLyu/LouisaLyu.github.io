## Goal

The goal of this project is to build a data visualization web page so that users can quickly see how the weather in two places changes over the next hours and days.

## Method

### Persona identification

The investigation begins with a persona, which helps establish a better understanding of the users’ needs. Built on research on student commuting and on how weather affects travel, the persona at the centre of this project is a student who commutes and checks the weather before leaving and again when plans change, comparing places before deciding whether to travel or stay put. Her needs include quickly comparing the weather in two locations and seeing short-term changes.

This leads to the initial design of the web page, which puts the weather data for two cities, chosen from a fixed list, side by side. This answers the persona’s first need: comparing two places without switching between forecasts. Time-range buttons answer the second, showing how the weather changes over the next day, seven days or 14 days.

### Comparison visualization and data summarization

Comparison also makes a forecast easier to understand. People tend to have a weak sense of what an absolute temperature feels like. However, when comparing it with their current city’s weather, they get a more concrete understanding of what the weather is like in a different city. This leads to the decision to visualize the two locations’ temperatures as line graphs so that people can compare quickly.

Additionally, to further support quick decisions, an interview is conducted to see what weather factors influence one’s decision when travelling. This identifies three things: chance of rain, temperature and wind speed. Because of this, advice cards are added to the top, as the image below shows, so the user no longer has to scroll around the app for this information.

### Design iteration

Following the initial prototype, a range of colours and layouts is explored, as shown below. The different layouts are used to find the least cluttered look, while the colours are chosen to resemble the sky, which fits people’s impression of “weather”. This experiment leads to the final look of the web page in the Outcome section.

## Outcome

The final product is a fully functional website that compares the weather between any two cities in the world through a search bar, using live forecasts from Open-Meteo (an open-source weather data service), so users no longer need to switch between cities when deciding whether to go out. The website shows the relative temperature between the two cities and a number of advice cards that inform the user of today’s suggested plans, so users can get an intuitive idea of what the weather is like rather than just abstract numbers. The data is switchable between the next 24 hours, seven days and 14 days, so users can see how the weather in both places changes over hours and days, supporting both short outings and long travel plans. The layout is kept minimal and the colours resemble the sky on a clear day, so the page stays easy to scan and matches people’s impression of weather.

## Insights

This project offers several pieces of insight and knowledge that are transferable to other works. Layout choices are most effective when informed by users’ needs, as with the advice cards placed at the top of the page because of the interview findings. Setting up a fully functional website with an application programming interface (API) and a data pipeline also builds experience for future web projects.
